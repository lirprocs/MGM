# MGM

Режим аутентифицированного шифрования MGM (Multilinear Galois Mode) по
Р 1323565.1.026-2019 и [RFC 9058](https://www.rfc-editor.org/rfc/rfc9058).

## Использование

`New` принимает любой блочный шифр с блоком 64 бита («Магма») или 128 бит
(«Кузнечик») и возвращает стандартный `cipher.AEAD`:

```go
block := ...                      // cipher.Block: «Кузнечик» (16 байт) или «Магма» (8 байт)
aead, err := MGM.New(block)       // имитовставка во весь блок
// aead, err := MGM.NewWithTagSize(block, 8) — укороченная, от 4 байт до длины блока

ct := aead.Seal(nil, nonce, plaintext, additionalData) // шифротекст || имитовставка
pt, err := aead.Open(nil, nonce, ct, additionalData)
```

- `nonce` — блок длиной 8 или 16 байт. По стандарту ICN занимает n−1 бит,
  поэтому старший бит первого байта должен быть нулевым: иначе `Seal`
  паникует, а `Open` возвращает ошибку. Один nonce с одним ключом дважды не
  применять.
- Дополнительные данные и текст не могут быть пустыми одновременно, а их
  суммарная длина должна быть меньше 2^(n/2) бит (для «Магмы» — меньше
  512 МиБ) — RFC 9058, п. 4.1. При нарушении `Seal` паникует, `Open`
  возвращает ошибку.
- `additionalData` — дополнительные имитозащищаемые данные: не шифруются,
  но входят в имитовставку.
- Длина шифротекста передаётся явно, поэтому любые байты (в том числе нули в
  конце) расшифровываются без потерь.

Исходные функции `Encrypt` / `Decrypt` (только «Кузнечик», шифротекст блоками)
сохранены для совместимости и помечены как устаревшие: `Decrypt` определяет
длину шифротекста срезанием нулей в конце, поэтому сообщение, у которого
шифротекст оканчивается байтом `00`, не проходит проверку, а нули в конце
открытого текста теряются.

## Исправления (ветка `fix-counters-length`)

1. **Счётчики `incr_r` / `incr_l`** увеличивали один байт без переноса. Через
   256 блоков (4 КиБ) гамма повторялась: `C₁ ⊕ C₂₅₇ = P₁ ⊕ P₂₅₇`, — а с первого
   переполнения байта результат расходился со стандартом. Теперь половина блока
   увеличивается как 64-битное число.
2. **Имитовставка при длине, кратной 16 байтам.** Если длина дополнительных
   данных или текста была кратна 16 (и не равна нулю), учитывался лишний пустой
   блок, и для `len(A) || len(C)` бралось не то `H`. Пример 2 из RFC 9058 не
   сходился. Теперь число блоков считается с округлением вверх.
3. **Новый интерфейс `New`** — для «Магмы» и «Кузнечика», с явной длиной.

## Исправления (ветка `rfc9058-limits`)

1. **Пустые данные и пустой текст одновременно.** Имитовставка в этом случае
   равнялась `E_K(0)` при любом nonce: выданную с одним nonce `Open` принимал
   с любым другим. RFC 9058 (п. 4.1 и 6) такой вызов запрещает — теперь он
   отвергается.
2. **Старший бит nonce** молча отбрасывался: два nonce, отличающиеся только
   им, давали одинаковые гамму и имитовставку. Теперь такой nonce отвергается.
   ⚠ Программа, которая передавала случайные 8 или 16 байт как есть, должна
   обнулять старший бит первого байта сама (`nonce[0] &= 0x7f`); результат
   шифрования от этого не меняется.
3. **Сумма длин.** Проверялась каждая длина отдельно, а стандарт ограничивает
   сумму `|A| + |P| < 2^(n/2)` бит.
4. **Умножение в поле** — окнами по 4 бита вместо одного: 57 нс вместо 157 на
   блок 128 бит и 31 нс вместо 66 на блок 64 бита (Ryzen 5 5600X). Таблица
   строится из секретного `H_i`, а индексы обращений к ней — полубайты
   открытого блока, поэтому обращений к памяти по секрету по-прежнему нет.
   Сверено с прежним побитовым умножением на 200 тыс. случайных пар.
5. Прежний `Decrypt`: сравнение имитовставки за постоянное время, ошибка
   вместо паники на пустом шифротексте. Срезание нулей в нём осталось — длину
   из блочного шифротекста восстановить нельзя; используйте `New`.

## Проверка

```bash
go test ./...
```

Тесты: оба примера RFC 9058 для «Кузнечика» (через `KuznEncrypt`) и для «Магмы»
(тестовая реализация в `magma_test.go`, сверена с примером RFC 8891);
совпадение `New` с исправленным `Encrypt` на длинах до 300 блоков; отсутствие
повтора гаммы; расшифрование шифротекста с `00` в конце; обнаружение искажений.
Тесты ограничений (`limits_test.go`): отказ на пустых данных с пустым текстом и
на nonce с единичным старшим битом, предел суммы длин, совпадение умножения с
эталоном, работа на месте, фаззинг `Seal`/`Open`:

```bash
go test -run '^$' -fuzz FuzzSealOpen -fuzztime 20s .
```
